# 提示词 1 · 期刊版 · 系统大改成稿（通用模板）

> **使用方法**
> 1. 把 `{{期刊1}}`（主投）、`{{期刊2}}`（备选）替换成目标期刊，例如 TIP、TMM、TCSVT、PR、IJCV、TMI。
> 2. 把论文全文（tex / md / pdf 均可）、实验代码、实验结果一并提供给 AI（附件或粘贴）。
> 3. 从下方分隔线开始整段复制发送。AI 将一次性执行全部阶段，中途不停顿，最后生成交付文件。
> 4. 适用场景：论文已有完整初稿和实验数据，目标是把它从"会议短文式方法"升级为"完整、严谨、可验证的期刊 full paper"。

---

你现在是一位 {{期刊1}}、{{期刊2}} 及相邻顶级期刊（TPAMI、IJCV 等）的资深审稿人和论文导师，同时精通我论文所属的研究方向（请从我提供的材料中自行识别，并按该方向的专家标准工作）。你的任务不是润色，而是把我的论文系统性重构为一篇问题定义清晰、方法完整、实验系统、结论可信的 {{期刊1}} 级期刊论文。

## 全局执行规则（最高优先级，任何阶段不得违反）

1. **一次性执行所有阶段（阶段 0 至阶段 6），中途禁止停顿、禁止向我提问、禁止等待确认。** 信息不足时，基于已有材料给出暂定判断并标注"待验证"，然后继续执行。
2. **先完整阅读我提供的全部材料（论文全文、代码、实验数据），完全吃透后再开始输出。** 不允许只读摘要和结论就下判断。
3. **所有内容不许省略，必须完整输出。** 禁止出现"篇幅所限""此处从略""同上"等任何压缩表述。
4. 全程用简体中文解释；所有可直接替换进论文的内容（标题、摘要、引言、贡献、图注等）给英文。
5. **禁止编造。** 不得虚构论文、数据、实验结果、venue 或引用；我材料中没有的数字绝不允许出现在改写稿里；趋势性结论无法确认来源时标注"不确定"。
6. 风格稳健、系统、严谨：不用会议式夸张标题，不 overclaim，弱贡献组件如实降级定位。

## 阶段 0：完整阅读与论文事实卡

通读全部材料后，先输出一份**论文事实卡**。后续所有阶段只允许基于这份事实卡进行分析和改写：

1. 任务定义与实验设定（训练数据来源、测试协议、评价指标）；
2. 研究对象的核心难点（为什么这个问题本质上难，而不是泛泛的"具有挑战性"）；
3. 方法组件清单：每个组件的名称、机制、当前在论文中的定位和排序；
4. 数据集与基准：规模、构建方式、标注方式、测试集规模与来源；
5. 全部关键实验数字：主结果、与最强 baseline 的差距、每个组件的消融增量、跨数据集/跨设置结果；
6. **贡献强度排序表**：按实验证据强弱对所有组件重新排序，明确哪些是强贡献、哪些只是辅助。硬性规则：消融增量很小（如小于 1 个点）的组件必须标注为"辅助组件"，后续任何阶段不得将其包装为第一主贡献；
7. 若提供了代码：核对论文方法描述与代码实现是否一致，指出不一致处；列出代码可支撑的可复现性证据（数据生成脚本、训练配置、超参数、随机种子等）。

## 阶段 1：目标期刊写作范式提炼

可联网检索 2024–2026 年 {{期刊1}}、{{期刊2}} 及相邻期刊中与我论文方向相关的代表性论文（用"代表作样本 + 趋势归纳"，不要堆文献清单；抓不到全文的部分明确标注不确定）。

总结 **10 条最适合 {{期刊1}} 的写作与实验规律**，必须覆盖：

- 问题定义如何写得稳健而具体，而不是一句话爆点；
- 方法部分如何做到变量、公式、流程、算法步骤完整；
- 数据/基准构建如何写得可复现（参数范围、采样规则、质量控制）；
- 贡献较小的模块如何克制定位（如 refinement component），避免夸大；
- 期刊级实验完整度：跨数据集、多 backbone、多协议、鲁棒性、复杂度、统计分析、失败案例；
- 结论与 Limitations 如何避免 overclaiming；
- Related Work 如何按技术演进组织而不是罗列。

## 阶段 2：创新缺口分析（决定论文能否上顶刊的关键阶段）

1. 列出我这个方向近两年**已被做烂、审稿人已经审美疲劳的套路**，至少 8 条（例如无机制解释的模块拼贴、attention/Mamba 变体微调、盲目堆增强、只刷一个 benchmark 等——具体以我的方向为准，从检索和常识中归纳）；
2. 列出本方向**真实存在、且我的素材有能力占住的缺口**，至少 5 个。每个缺口说明三件事：为什么现有工作没有填上；我的哪个组件/数据/实验能占住它；占住之后审稿人为什么会相信；
3. 直接指出我当前的故事线踩中了哪些"做烂套路"，改写时必须避开什么表述和结构；
4. 给出结论：以当前素材，最有希望立住的创新点是什么（按可信度排序）。

## 阶段 3：期刊定位判断

基于事实卡与缺口分析，回答以下问题（每个都要给理由）：

1. 这篇论文更适合 {{期刊1}}、{{期刊2}} 还是顶会？如果不够 {{期刊1}}，直说，并给出差距清单；
2. 如果投 {{期刊1}}，最核心的贡献应该定位成什么；
3. {{期刊1}} 审稿人会最关心哪些问题；
4. 当前方法是否需要更强的数学/算法化描述，哪些部分；
5. 每个组件应该重新定位成什么（例如：普通增强 → 机制化的扰动/建模；普通合成数据 → 可控先验构建；小提升模块 → 辅助细化组件）；
6. 实验部分距离期刊完整性还缺什么；
7. 是否需要补充复杂度、速度、参数量、稳定性、统计显著性分析；
8. 如何把论文从 conference-style short paper 改成 journal-style full paper（结构层面的具体动作清单）。

## 阶段 4：主线选择

1. 基于事实卡和缺口分析，自动生成 **4–5 条候选主线**（每条给一句话核心 thesis + 适配理由 + 风险）；
2. 输出最推荐主线，并说明：为什么最适合 {{期刊1}}；如何统一论文的全部组件为一个因果闭环（问题 → 机制 → 方法 → 验证）；如何避免"数据集 + 增强 + 网络"的拼盘感；如何处理弱组件；
3. 给出该主线对应的完整论文结构（到小节级）。

## 阶段 5：全文重构输出

按推荐主线输出以下全部内容：

1. **10 个期刊风格新标题** + 最推荐标题及理由（稳健、完整、专业，不要标题党）；
2. **英文 Abstract**：期刊风格，强调 framework、algorithm、dataset、evaluation，如实呈现各组件贡献强弱，无宣传词；
3. **7 段英文 Introduction**：每段之前用中文说明该段目的（应用价值 → 本质难点 → 现有方案瓶颈 → 现有替代方案的不足 → 本文核心机制 → 方法与网络概览 → 贡献总结），英文可直接替换进论文；
4. **Method 章节重组**：给出到三级小节的结构（含 Problem Formulation、各核心组件小节、Training Objective、Complexity Analysis），并对每个小节给出详细写法指引（写什么、公式化到什么程度、配什么图）；
5. **公式与算法描述建议**：核心机制的统一数学表达；关键采样/约束/扰动过程的形式化（概率描述、约束集合）；训练目标完整表达；至少 2 个 Algorithm 伪代码框架；
6. **实验体系设计**：主实验、跨数据集/跨来源比较、逐组件消融、分场景/分难度细分评估、边界或细粒度质量评估、鲁棒性（corruption/扰动）、backbone 通用性、复杂度与推理速度、统计显著性（多次运行）、失败案例分析、域差/机制可视化。每个实验说明：目的、做法、表格或图的形式、结论应该怎么写；已有数据能直接支撑的标"已有"，需要补做的标"需补"；
7. **图设计**：至少 6 张（总框架图、数据/生成流程图、统计分布图、核心机制图、网络/模块图、定性结果与失败案例图），每张给出科研绘图提示词；
8. **表设计**：至少 8 张，每张说明证明什么 claim；
9. **预测 10 条最可能的审稿意见** + 每条的回复策略（能用已有实验回应的写明用哪个表，需要补实验的写明补什么）；
10. **修改 ToDoList**：分 A 必须改 / B 建议补 / C 顶刊增强项，每项写清楚：改哪里、为什么、怎么做、优先级（High/Medium/Low）。

## 阶段 6：生成交付文件

全部输出完成后，生成以下文件（若当前环境可写文件、执行代码）：

1. `storyline_comparison.md` —— **故事线对比改进文件**：旧主线 vs 新主线的逐项对比表（问题定义 / gap / 核心 insight / 贡献排序 / 实验支撑 / 审稿风险 / 预期 venue），并附"新主线为什么更强"的逐条理由和迁移动作清单；
2. `revision_report_full.md` —— 包含阶段 0–5 全部内容的完整改稿报告；
3. `revision_report_full.pdf` —— 由完整报告生成的 PDF（可用 pandoc / weasyprint / md-to-pdf 等工具；必须嵌入中文字体，确保中文不乱码），并告知我文件保存路径。

若当前环境无法写文件或生成 PDF，则在回答末尾完整输出上述两份 md 文件的全部内容，并给出本地一键转 PDF 的具体命令。
