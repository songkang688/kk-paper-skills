# 起草工作流：从证据包或中文稿到一篇完整英文初稿

适用两种任务，共用同一套骨架：

- **模式一｜从零起草**：学生给一堆证据（方法细节、模块清单、实验数据、要投哪儿），要一篇完整英文初稿。
- **模式二｜中翻英**：学生给一篇中文稿（或分节的中文提纲），要按目标风格产出英文稿。**这不是翻译任务，是用中文稿当事实来源的重写任务**——逐句直译出来的英文必然带中文的段落逻辑，与目标风格处处相抵。

不适用：改已有英文稿（走 `polish_workflow.md`）；只写单独一个章节（直接按 `section_playbook.md` 对应节写，不必开这套编制）。

---

## 零、为什么起草用并行子 agent，润色却不用

润色是九个人改**同一份稿子**，互相撞车，父节点疲于裁决，所以改成了老师一个人顺着改。起草相反：各节是**从零新写的不相交产物**，共同依赖的只有一份只读的事实包，并行的人之间没有共享可变状态，不会撞车。分节并行在这里是净收益——每节的写作套路差异极大（引言讲故事、方法讲数据流、实验讲证据纪律），一个 agent 专注一节能把该节的 playbook 吃透。

代价花在哪里心里要有数：**并行省下的时间，一部分要还给融合**。五路稿子的术语、缩写、贡献口径必然有出入，父节点的融合步骤（第四节）是这个工作流的成败所在，不是走过场。

---

## 一、产物约定：一次任务一个文件夹

**所有产物放进论文目录下的同一个任务文件夹**，不散落。外层带 venue 与时间戳
`yfn_<venue>_<YYYYMMDD-HHMM>/`（venue 从 `paper_context` 的 anchor 复用），
里层从零起草叫 `draft-vN/`，中翻英叫 `c2e-vN/`，N 递增，旧任务文件夹绝不覆盖：

```
<论文目录>/yfn_ICASSP_20260831-1430/draft-v1/
  00-初稿总览.md / .pdf        ← 父节点写：各节怎么融合的、统一了什么口径、页数词数账
  00-需作者确认.md / .pdf      ← 全部 [TODO:] [REF:]、术语抉择、翻译取舍，一处一条
  01-title-abstract-conclusion.md / .pdf
  02-introduction.md / .pdf
  03-related-work.md / .pdf
  04-methods.md / .pdf
  05-experiments.md / .pdf
  draft/                       ← 融合后的完整初稿，能独立编译
    main.tex / main.pdf / main.docx（+ .bib、.sty、figures/）
  _work/                       ← 内部账目，不算交付物
    fact_pack.md               ← 唯一事实来源
    fusion_notes.md            ← 融合裁决记录
```

每份 md 照旧配同名 PDF（`python md2pdf.py <任务文件夹>` 一次转完）。正稿 PDF 用 LaTeX 真编译，Word 版用 pandoc（第五节）。

## 二、第一步：问诊 + 事实包（父节点亲自做，不下放）

### 问诊

沿用 `polish_workflow.md` 第零节的方式，起草任务重点问三件事：

1. **投哪儿？** 决定模板、页数预算、有没有独立 Related Work、摘要词数区间。没定就按领域惯例猜一个，明说让他确认。
2. **证据齐不齐？** 按 `SKILL.md` 第二节的表逐节对：模块清单与目的、数据流、公式、数据集、消融数值、比较结果。**实验跑没跑要单独问清**——没跑的按占位符纪律写，绝不编。
3. **图表有没有？** 有图就要图和图注素材；没图就只规划图表位置与 label 名，正文照常引用，图本身进确认清单。

### 事实包 `_work/fact_pack.md`

把问诊拿到的一切整理成一份结构化文档，是全工作流**唯一的事实来源**：

- 任务名、方法总名与缩写、投稿目标与页数预算
- 模块清单：名称、缩写、目的（解决哪类信息缺失）、机制、输入输出
- 数据集、指标、消融变体与数值、比较结果（含输掉的指标）、代价维度
- 公式与符号表；引用可用清单（学生给了哪些文献）
- 图表规划：每张图的角色、label 名（`fig:framework` 这类，后面各节引用全靠它）
- 红线登记：哪些数字没有、哪些实验没跑——这些位置各节只准写 `[TODO:]`

**模式二附加**：把中文稿按节切开放进事实包，再建一张**术语对照表**（模块名中英、缩写、数据集名、指标名、关键动词），父节点先定死，否则五路各译各的，融合时对不上。

缺的事实先问学生；问不到的登记成确认项。**事实包没写的东西，任何 agent 不得自己补。**

## 三、第二步：并行派发五个分节 agent

### 编组

| # | 负责 | 为什么这么分 |
|---|---|---|
| 01 | **Title + Abstract + Conclusion** | 三者是同一组事实的三级压缩，必须一人写：模块宣告的措辞、强度词、诚实声明要三处同频，Conclusion 的目的从句复述要与 Abstract 呼应 |
| 02 | **Introduction** | 讲故事：代价 → 分类 → 难点枚举 → 信息缺失 → 贡献列表，套路独立成体系 |
| 03 | **Related Work** | 谱系分节 + 定位段收尾；会议模板没有独立 RW 时写成谱系段落，融合时由父节点并进 02 |
| 04 | **Methods** | 总览先行、逐模块目的先行、损失末位；公式与符号只能来自事实包 |
| 05 | **Experiments** | 协议与消融在前、比较在后；没跑的实验按占位符纪律写，宁短勿注水 |

五路同时开工，互相不通信，也**不许引用彼此的产文**——都只从事实包取材。交叉引用（图表、公式、章节）一律写事实包里规划好的 `\ref{}` label，编号由 LaTeX 编译时自然解决。

### 每个 agent 的任务书必须包含

1. 事实包全文（或路径），声明它是唯一事实来源
2. `SKILL.md` 第三节红线 + 第四节六条主干
3. 该节的 `section_playbook.md` 对应节与 `workflow_and_templates.md` 骨架模板
4. 词数预算（父节点按页数预算拆好再派）
5. 输出格式（见下）与返回给父节点的账目格式

**模式二附加纪律**：忠实于中文稿的技术内容，不加不减事实；结构可以按英文套路重排（中文稿常把动机铺三段，英文按 playbook 收成一段），但**每一处挪位和删除都要登记**；中文里的客套话、自谦句、政策性套话不译，列进"删了什么"；英文惯例要求但中文稿没有的成分（定位段、贡献列表），内容能从中文稿推出就补，推不出就 `[TODO:]`，不代学生发明。

### 每个 agent 产出一份 md，结构固定

```
# <部分名> 初稿 — <论文名>

## 成稿
（英文，可直接进 tex；缺口按红线标 [TODO:] [REF:]）

## 我是怎么组织的
（中文两三段，导师给学生讲思路的口吻：为什么难点枚举放第二段、
 为什么这个模块先讲。照 review_voice.md，不写规则编号）

## 用到的事实
（事实包的哪些条目进了哪一段——给父节点融合、给学生核对）

## 需要你确认的
（[TODO:] [REF:] 逐条 + 我拿不准的表述；模式二再加"挪了什么、删了什么"）
```

同时向父节点返回账目：词数、用了哪些事实条目、待确认项清单。

## 四、第三步：父节点融合（成败所在，一项不能省）

五份稿子到齐后，父节点逐项过这六关，裁决记进 `_work/fusion_notes.md`：

1. **术语与缩写统一。** 全文首次出现给全称加缩写，之后只用缩写。五份稿子各自的"首次"不等于全文的首次——通常 Abstract 定义一遍、Introduction 再定义一遍、后文全用缩写。
2. **模块-贡献-消融闭环。** Abstract 的模块巡览 = Introduction 的贡献列表 = Methods 的小节 = Experiments 的消融行，四处一一对应。对不上就以事实包为准改稿，不许改事实。
3. **重复内容裁决。** Intro 的难点枚举与 Abstract 首句、RW 定位段与 Intro 的 gap 句，天然相似。保留各自层级的版本，但措辞不得逐字相同；发现两节把同一句写重了，留信息密度高的那处。
4. **时态与锚点纪律全篇复查。** 单节各自合规不等于拼起来合规——最常见的漏网是 01 号写 Conclusion 时用了表号（单看那节没有 Results 可引，拼进全文就违反锚点规则）。
5. **页数预算按位置算。** 教训直接从润色工作流搬来：总词数达标不代表不溢页。拼完先编译一次，超页先砍重复与背景铺垫，永不砍目的从句与诚实声明。
6. **`\ref{}`、`\cite{}`、`\label{}` 核对。** 每个引用的 label 都在事实包的规划清单里；引用键都在 .bib 里；无 undefined reference。

融合时对各 agent 稿子的每处改动，在 `00-初稿总览.md` 里向学生交代（照 `review_voice.md`：正文讲改了什么为什么，末尾附核对清单给复核用）。`00-需作者确认.md` 则把五份稿子的确认项合并去重，按"缺了会怎么样"排序——缺消融数值排在缺一条引用前面。

## 五、第四步：三格式落稿

| 格式 | 怎么出 | 定位 |
|---|---|---|
| `main.tex` | 套问诊定下的投稿模板，融合稿分批填入、分批编译 | 唯一真实来源 |
| `main.pdf` | `pdflatex` + `bibtex` + `pdflatex` ×2 | 排版以它为准 |
| `main.docx` | pandoc（见下） | 给导师/合作者批注用的工作版，公式转成 Word 公式对象，双栏会变单栏，**排版不以它为准** |

### Word 转换的通用方法（不含本机专属路径）

```bash
pandoc main.tex --citeproc --bibliography=<你的.bib> -o main.docx
```

pandoc 的查找顺序：环境变量 `YFN_PANDOC` → PATH → 各系统常见安装位置（Windows：`%LOCALAPPDATA%\Pandoc`、`C:\Program Files\Pandoc`、`D:\tools\pandoc`；macOS：`/usr/local/bin`、`/opt/homebrew/bin`；Linux：`/usr/bin`）。

找不到 pandoc 时：**照常交付 tex 与 PDF，明确告知 Word 未生成**，附安装命令（Windows `winget install JohnMacFarlane.Pandoc` 或下载便携版 zip 解压即用；macOS `brew install pandoc`；Linux `apt install pandoc`），不要静默跳过，也不要用别的格式冒充 docx。

pandoc 对复杂 tex（自定义宏、双栏浮动体）可能丢样式——丢了不算错误，Word 版本来就是批注用的工作版，但要在 `00-初稿总览.md` 里提一句哪些成分在 Word 里走了样。

**会议模板的 `.sty` 常让 pandoc 直接报错**（实测 ICASSP 的 `spconf.sty` 是底层 TeX，pandoc 解析到一半就停）。通用解法：把 `.tex`、`.bib`、`figures/` 复制到一个临时目录，**不带 `.sty`**，在那里转——pandoc 对找不到的宏包只发 WARNING 并跳过，正文、公式、图表照常转出。不要为了迁就 pandoc 去改正式 tex 源文件。

## 六、验证闸门（初稿版）

编译干净只是起点，逐项过：

```
# 1. 排版：页数在预算内；末页规则符合投稿要求；无 overfull、无 undefined reference
# 2. 事实一致：正文每个数值、公式、模块名都能回指到事实包条目；[TODO:] [REF:] 与确认清单一一对应，无漏登记
# 3. 闭环：模块-贡献-消融四处对齐（第四节第 2 关的复查）
# 4. 语言残留（模式二必查）：英文成稿里无中文字符、无中式直译痕迹段落
# 5. 风格自检：SKILL.md 第九节清单逐项过
# 6. 交付完整：tex/pdf/docx 三格式齐（docx 缺 pandoc 时已明确告知）；每份 md 有同名 PDF；全部产物在同一个任务文件夹里
```

## 七、最容易踩的四个坑

1. **事实包写薄了。** 五个 agent 只见事实包，包里没写的它们就只能标 TODO 或自由发挥——前者稿子千疮百孔，后者踩红线。父节点在问诊阶段多花十分钟，比融合阶段返工五路稿子便宜得多。
2. **贡献列表由 02 号单独定稿。** 贡献条目是 Abstract、Introduction、Conclusion 三处共用的骨架，实际应当在事实包里就定好草案，02 号只负责措辞。否则 01 号与 02 号各写一版贡献，融合时必然二选一重写。
3. **模式二把"翻译腔"当忠实。** 中文稿一句"该方法具有较好的鲁棒性"直译成 `has good robustness` 是空话，目标风格要求落到条件式表述。忠实的对象是**技术事实**，不是中文的句式和修辞习惯。
4. **图表还没有就写死编号。** 正文引用一律用 label（`\ref{fig:framework}`），绝不手写 `Figure 2`——图的增删会让手写编号全体错位，而 label 由编译器结算，永远是对的。
