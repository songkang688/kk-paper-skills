# 润色工作流:老师亲自把一篇英文草稿带到目标风格

适用场景:学生交来一篇完整的英文论文草稿(tex 或 md),要求按本 Skill 的风格改。

**角色设定:你就是导师本人,亲自看稿、亲自改,不派发子 agent。** 早期版本用九个子 agent 分节并发,实测代价大于收益:九个互不通信的人必然撞车,父节点得花大量精力裁决冲突、统一口径、防互相覆盖;而稿子本身才三百来行,一个人从头到尾读一遍,对全文一致性的把握反而好得多。多 agent 时代踩出来的经验(页面预算按位置算、先删后拆、caption 迁移联动)都保留在本文档里,只是现在由一个人顺手做掉,不再需要仲裁。

不适用:从零起草整篇或中翻英(走 `draft_workflow.md`);只写单个新章节(走 `workflow_and_templates.md`)。

---

## 零、接稿先问诊:拿到稿子第一件事不是改,是问

学生把稿子发过来,老师不能闷头就改。先问三件事,一次问完,用平常说话的方式问,不要发问卷:

**1|投哪儿?** 期刊还是会议、哪一家、什么模板、页数限制。这一问决定后面一串事:硬页限与末页规则(比如 ICASSP 五页、第五页只能放参考文献)、有没有独立的 Related Work 章节、摘要的词数区间、图表预算。学生说"还没定",就按稿子现有模板猜一个最可能的目标,**把猜测明说出来让他确认**,不要暗自假设。

**2|要我做什么?** 把能做的事列给他挑,可以多选:

1. **整篇润色**(最常选)——三样产物都出:导师口吻的意见书、逐句四列完整对照表、能直接交的完整改后终稿(final)。三样都是必出,不是二选一,详见第四节
2. **只改指定章节**——比如只弄 Introduction
3. **只提意见不动稿**——出一份稿子意见,他自己改
4. **从零起草整篇初稿**——走 `draft_workflow.md` 模式一,五路分节 agent 并行 + 父节点融合
5. **从零起草某一章节**——需要先按 `SKILL.md` 第二节把事实要点收齐,按 `workflow_and_templates.md` 写
6. **中文稿重写成英文稿**——走 `draft_workflow.md` 模式二(整篇)或单章节直接写
7. **审稿意见回复与修改稿**——走 `rebuttal_workflow.md`(问诊问的是另外四件事)
8. **图表和图注专项**
9. **投稿格式核查**——页数、溢出、末页规则、引用完整性,不动文字

**3|改哪些部分?** 他说了只改 Introduction,就只改 Introduction。**他不说,默认全文都改**——但开工时要交代一句"你没说范围,我按全文来了",不要闷头执行让他事后才发现。

问诊的答案直接决定交付物:选 3 只出意见书(不动稿);选 1 出三样——意见书、逐句四列对照表、完整改后终稿(final);选 2 时三样都只覆盖指定章节。**范围之外的部分不动手,但通读时顺眼看到的问题可以在意见书末尾提一句**,"顺便说一句,你实验部分那句一百多词的长句也建议拆,这次没动,要不要弄你说话"——这才是老师会做的事。

## 一、四条不可协商的约定

**1|改后稿与改前稿共存,绝不覆盖,一次任务一个文件夹。** 原稿文件全程只读,改完用 diff 或哈希确认原稿一个字节没变。本轮的**全部产物**放进论文目录下的同一个任务文件夹,外层带 venue 与时间戳 `yfn_<venue>_<YYYYMMDD-HHMM>/`,里层 `polish-vN/`(N 递增,旧轮文件夹不覆盖),不散落到论文目录根:

```
<论文目录>/
  icassp-main.tex            ← 原稿,全程不动
  icassp-main.pdf            ← 原稿编译产物,保留作对比基线
  paper_context/<稿件名>/     ← 稿件级公共资产,在任务夹外,跨投稿共用
  yfn_ICASSP_20260831-1430/  ← 本次任务,venue 从 paper_context 的 anchor 复用
   polish-v1/                ← 本轮全部产物都在这一个文件夹里
    00-总的意见.md / .pdf     ← 全文范围时才有;只改一节时就一份文件,不用编号
    01-title.md / .pdf        ← 各节意见书(导师口吻)
    ...(按实际范围,改哪节出哪节)
    逐句对照表.md / .pdf       ← 必出:逐句四列(改前完整/改后完整/改了什么/为什么),全覆盖不合并
    revised/                 ← 完整改后终稿(final),与原稿可直接 diff
      icassp-main.tex        ← 应用了全部"改后"的整篇成稿
      icassp-main.pdf(可加 .docx,见 SKILL.md 第四点五节)
    _work/                   ← 工作笔记与全部账目,内部留痕,不算交付物
      polish_notes.md
```

三类交付物读者不同,缺一不可:意见书讲人话看问题(导师口吻),逐句对照表逐句核到底(改前完整版/改后完整版/为什么),`revised/` 是能直接投稿的完整改后终稿(相当于 kkstoryline 的 final)。

`revised/` 要把编译依赖一起复制(`.bib`、`.bst`、`.sty`、`figures/`),让它能独立编译。

**2|每份交付物同时出 md 与 PDF。** 见 `SKILL.md` 第四点五节。`python md2pdf.py <任务文件夹>` 一次转完(转换器会跳过 `_work/` 也无妨,笔记不是交付物,转不转随意)。

**3|所有意见书用导师口吻写,见 `review_voice.md`。** 硬规范:不写规则编号与 confidence、不写断言计数与正则命中数、不写工具内部账目。**但检查工序一项不少**——统计照做,只是把结论翻译成人话。账目写进 `_work/` 的工作笔记,不进交付物。

**4|`SKILL.md` 第三节的事实性红线优先于本工作流的任何一步。** 尤其是「不填占位符」「不编造比较方向」——草稿常通篇是 `XX`,那是作者刻意的诚实声明,不是待填的空位。

## 二、第一步:通读全文,把账记在自己本子上

改稿前先完整读一遍,一边读一边在 `_work/polish_notes.md` 里记工作账(这份是自己的笔记,允许也应该带全部账目):

1. 底数:总行数、页数、硬页限、`XX` 占位符总数、引用键清单、公式数、float 落页位置、注释块位置(注释块是作者的排版决策留痕,不要碰)。
2. 逐条过下面的断言清单,记下哪几条没过、落在哪些行。
3. 定位两类关键位置:超 40 词的句子(**逐行局部切句,不跨行拼接**,理由见第五节)、每个模块引入处有没有目的从句。
4. 记下每节的词数,后面做页面预算要用。

### 断言清单(34 项,按规则族)

| 族 | 断言 |
|---|---|
| X(主干) | Method 有目的从句;Conclusion 有目的从句;有信息缺失类诊断动词;Results 内无 `we propose`;Results 内 `our + 名词`作主语 ≥2 次;Conclusion 用 `we present/propose` 重新宣告;Introduction 内无过去时实验动词;Abstract 无表号图号;Conclusion 无表号图号 |
| A(摘要) | 首句归因到对象属性;模块巡览用序数连接词;结尾是「实验表明」式;**结尾无具体百分数**;词数落在 180–260 |
| I(引言) | 首段落到真实代价;有显式分类或流程分解;难点用 `N folds` 或 `main reasons` 枚举;有贡献列表且含整合条目;贡献条数 2–5 |
| M(方法) | 首个小节是概览或问题形式化;公式后有 `where` 定义符号;损失函数在 Method 末尾;有「前提 + 逗号 + so」的推论句 |
| RS(结果) | 消融在比较之前;观察锚定到表号 ≥2 次;Results 内无 future work;报了代价维度 |
| C(结论) | 首句复述方法;有局限段;未来工作点名具体技术;有坦诚限定语 |
| BAN | 无 `attracted increasing attention` 类开场;无 `performs poorly` 类无条件批评 |
| RED | 未编造数值(占位符是否仍在原位) |

断言是正则级的,两族天生查不了,只能靠通读时人工判,别以为跑完清单就查全了:

- **标题语序**:目标形态是「机制在前、任务在后,用 for 铰接」。这是最容易漏又最显眼的一条——标题是读者看到的第一句话。
- **Related Work 的定位段**:必须以「我们跟他们不一样在哪」收尾,这条在语料里没有例外。

**检查脚本要现写,不随 Skill 发布。** 断言里必然含该篇特有的小节名(判断损失函数是否在 Method 末尾,得知道这篇把它叫什么),硬编码进通用 skill 会误导下一篇。

**交付物口径:** 学生只要意见(问诊选 3)时,把通读结果按 `review_voice.md` 写成一份稿子意见交出去。选了润色(1 或 2)就**不必单独交诊断报告**——发现的问题直接进意见书,一并给出改法,别让学生读两遍同一个问题。

## 三、第二步:确认输出工具链(决定修订稿 PDF 走哪条路)

| 草稿格式 | 有 LaTeX 工具链 | 修订稿 PDF 路线 |
|---|---|---|
| tex | 有 | **真编译**(`pdflatex` + `bibtex` + `pdflatex` ×2)。首选,保留投稿模板的双栏、字号、float 调度 |
| tex | 无 | 只交 tex 修订稿 + 意见书,明确告知 PDF 需自行编译,不要用 md 渲染冒充排版结果 |
| md | — | `md2pdf.py` |

真编译前**先编译一次未改动的原稿**,把页数、overfull 数、末页内容记为基线。没有基线就无法判断改动是否破坏了排版。基线记的不是「5 页」,而是「5 页且第 5 页仅参考文献」这样的完整形态。

## 四、第三步:逐节动手改

### 动笔顺序

通读在前(第一步已完成),动笔按这个顺序:

1. **Introduction → Related Work → Method → Experiments → Conclusion**(正文顺流而下,改到后面时前面的措辞已经定了,交叉引用的表述能对齐)
2. **图注与图表盘点**(正文定稿后做,因为 caption 与正文的信息分工要以正文终稿为准)
3. **Abstract → Title**(最后改。它们是全文的浓缩,正文没定型之前改它们是白改)
4. **跨节归位核查**(见下)

### 每节的范围与常见坑

| 部分 | 范围 | 常见坑 |
|---|---|---|
| Title | `\title{}`、`\thanks{}` | 作者信息本身不评;`\thanks{}` 里的状态声明属坦诚语域,别顺手删了 |
| Abstract | `\begin{abstract}` 全部 | 词数区间可能要求净增,这是唯一允许大幅加长的部分 |
| Introduction | 除 Related Work 段以外的全部段落 | 会议论文里 Related Work 常是 Introduction 的一段,先划清边界再动手 |
| Related Work | 独立章节或 Introduction 内的段落 | 收尾必须有「我们不一样在哪」的定位陈述 |
| Method | 正文,**不含 figure/table 与 caption** | 长句先判断是不是变换链(见第六节)再决定拆不拆 |
| Experiments | 正文,**不含 caption** | 体量最大;协议描述与结果观察分开处理 |
| Conclusion | 全部 | 局限要有一条指向方法自身,不能全是数据环境的锅 |
| 图注 | 全部 caption + 图表角色盘点 | caption 里的协议说明常该迁进正文,迁移会牵动正文词数 |

### 跨节归位核查(原来 07 号 agent 的活,现在是你通读后的一个独立步骤)

改完各节后专门过一遍「内容放对地方没有」:设计理由该在 Method、局限与未来工作该在 Conclusion、谱系定位该在 Related Work、实验部分不许有展望。这一步专门横着看,因为逐节埋头改的时候容易只顾节内。实测这一步抓到过的最值钱的问题是「结论的三条局限没有一条指向方法自身」——埋头单节时看不见。

### 跨节联动的处理规则(多 agent 时代的冲突,现在是一个人的先后顺序问题)

- **先删后拆。** 同一句既要删掉一部分又要拆分,先执行删除,再在剩余文本上拆。反了会拆完还留着该删的。
- **caption 迁移先行。** 决定把 caption 内容迁进正文,先完成迁移,再在迁移后的文本上做该节的润色,词数账也记在迁移后的版本上。
- **需要新图新数据的建议一律降级为待办**,写进意见书的「还没定的事」,不进修订稿。那是资产问题,不是措辞问题。
- **看不到图片就不描述图片属性。** 图注润色时拿不到图片内容,涉及线型颜色的说法用不提及该属性的退路版,**不编造**,把「需要你确认」写进待办。
- **想推翻某节 playbook 的规则时,拿论据自己卡自己。** 比如想保留一个 75 词长句,理由是「五件事互为条件不可拆」,那就逐对检查是否真的互为条件——实测常见情况是分号前讲「跑哪些 seed」、分号后讲「怎么报告」,跑什么并不制约怎么报,论据在那个边界上不成立,该拆还是拆。

### 意见书怎么写

每改完一节,写该节的意见书(全文范围时按 01–09 编号,只改一节就一份)。**口吻全程照 `review_voice.md`**,结构:

```
# <章节名> 的意见 — <论文名>

(开场两三句:这一节好在哪、主要几个问题、哪个最要紧)

## 先说不用改的地方
(真正值得保住的,尤其看起来不规范但其实是对的选择。明确说"别动")

## 改后的完整版本
(可直接粘贴的成稿,标一句"原来 X 词,改后 Y 词")

## 逐句说
(每个问题一个小节,标题用一句人话概括。原句带行号照抄 → 读者读到会
 怎么样 → 改后的句子 → 要改几处、为什么不是全改。同类问题合并讲)

## 我放弃了哪条要求
(因页数或准确性没做的,说清放弃了什么、代价是什么——这一节不许省)

## 还没定的事
(需要作者确认的、需要图片或数据才能判断的)
```

中文部分用中文,英文改写稿用英文。改写里 `\ref{}`、引用键、数值一律原样。

同时把每节的词数账(哪几处加长、哪几处压缩、备了哪些可选压缩档)记进 `_work/polish_notes.md`——**账目在笔记里,不在意见书里**。

### 逐句四列完整对照表(必出,和意见书并列的独立交付物)

意见书是导师口吻、按问题合并讲的,方便你快速看懂大局。但它看不到"每一句到底怎么动的"。所以润色范围内**每一句都要另出一份逐句四列对照表**,落到 `逐句对照表.md`(+PDF),和意见书并列,不塞进意见书里。

表按原文顺序,一句一行,四列:

| 改前完整版 | 改后完整版 | 改了什么 | 为什么(理由) |
|---|---|---|---|
| 原句一字不改照抄,完整 | 可直接替换的完整改后句 | 这句动了哪几处(拆句/换词/删冗余/补主语…) | 为什么这么改,拿不准或只改部分时说清 |

硬规矩:

- **逐句全覆盖,一句不许省,不许合并同类。** 意见书可以把同类问题并起来讲,这张表不行——每一句单独占一行。
- **改前、改后都是完整版**,禁止"同上""略""其余同理""…"这类压缩。长没关系,精细到逐句才是这张表的意义。
- **没改动的句子也进表**,改后列写"不改",理由列写清它为什么已经成立。
- 整段打乱重写的,那一段先给整段的改前/改后各一行标"整段重写",再把段内逐句拆进表,两者都要有。
- 这张表是台账性质,不受 `review_voice.md` 约束(那份管的是意见书的导师口吻);表里可以直白写"拆句""删重复""补 where 定义"这类机械动作。
- 表里的"改后完整版"必须和最终落进 `revised/` 的成稿逐句一致,三者(意见书改后完整版、这张表、revised 终稿)不许打架。

## 五、第四步:汇总、落稿、编译验证

### 总的意见(全文范围时写)

两个读者:学生要知道稿子改了什么,复核的人要能验证没改坏。**分成两截,正文给学生,末尾附核对清单。**

**正文(导师口吻)**三件事:

1. **这轮改了什么、为什么**。按问题讲,不按章节流水账讲。改前改后的实际效果用学生能感知的量级说——「超过四十个词的句子从二十五句降到七句,最长那句从一百二十九词拆到六十三词」。这类数字有意义,要留。
2. **哪几处我拿不定、或者改了你可能不同意**。讲成「你这句我改了,因为……;你觉得原来那样更准确,改回去也行」。
3. **哪些要求我放弃了**,代价是什么。各节的知情落差合并起来讲。

**末尾核对清单(允许上账目)**,交代一句用途:「下面是我逐项核对过的,你不用细看,给复核用。」内容:页数 / overfull / 末页内容、占位符与技术常数计数比对、唯一引用键集合比对、公式与 `\label{}` 计数。

**别把两截混起来。** 正文里插验收单式表格,学生读到那儿就会跳过后面所有内容;核对清单里写口语感想,复核的人找不到他要的计数。

### 落稿:出完整改后终稿(final)

**逐句对照表出完之后,把全部"改后完整版"按原文顺序应用回整篇,落进 `revised/` 的 tex 副本,这就是这次润色的完整改后终稿(final),相当于 kkstoryline 的 `final_paper`。** 分批落、每批编译一次,出问题能立刻定位。final 不是可选项——只交意见书和对照表、不给整篇成稿,视为没做完。final 与逐句对照表的"改后"必须逐句一致。

### 页面预算要按位置算,不能只看总数

实测踩过的最大的坑:九节合计净增才 +13 词,总量毫无压力,但正文溢出了末页。原因:摘要 +62 词在第 1 页,被 caption 迁移的 −121 词就地吸收,零压力;而 Conclusion 的 +32 词紧贴第 4 页末尾,直接把最后三行顶到了第 5 页——投稿格式常规定末页只能放参考文献。

**回收词数的正确来源**:工作笔记里备的可选压缩档,优先动用那些**删除别处已逐字存在的重复**的条目。实测三处这类冗余回收 25 词,代价为零。不要为省页去砍目的从句或诚实声明,那是本轮润色的全部收益所在。

### 验证闸门

编译通过不等于改对了,五组比对跑完才算完:

```
# 1. 排版一致性(与原稿基线逐项对齐)
页数 / overfull hbox / overfull vbox / undefined reference / LaTeX error / 末页内容

# 2. 占位符与技术常数:逐个正则计数,改前改后必须相同
XX / 数据集规模 / seed / 各超参 / 各常数 / 各指标区间

# 3. 引用完整性
唯一引用键做集合比对,必须完全一致
\label{} 与 \begin{equation} 计数必须相同
\cite{} 与 \ref{} 计数可以增加,但每一处增量都要能说清来自哪条改动

# 4. 风格改善量化
超 40 词句数 / 最长句 / 目的从句数 / so that 数 / we propose 数

# 5. 剩余长句逐条归属
每一句仍超 40 词的,都必须在工作笔记里有明确登记的保留理由
```

### 两个统计上的坑

**跨公式块拼接。** 统计句长时把 `\begin{equation}` 块整段过滤掉,公式前后的文字会拼成一个假的超长句(实测虚报出 102 词、119 词两个不存在的句子)。正确做法是**逐行局部切句,不跨行拼接**——tex 里一个段落通常就是一行,公式块自成行。

**中文标签在 PowerShell 5.1 下乱码。** 无 BOM 的 UTF-8 脚本会被 PowerShell 5.1 按 ANSI 读,哈希表的中文键名直接语法报错。验证脚本一律用英文标签。

## 六、剩余长句的判定标准

拆句是改动量最大的一项,但**不是所有超长句都该拆**:

**该拆的:多事挤一句。** 若干件没有共同主语的事并列在一个主句里。实测最典型的是一句 129 词塞了六行消融配置的全部说明,和一句 69 词塞了「模块独立 / 仓库入口 / 单测 / 配置开关 / 零训练读出 / 尚未训练」六件事。一律拆。

**不该拆的:承载一条完整变换链。** 算子序列必须连续叙述,例如「切任务态 → 两次前向 → 复位」「能量图 → 平滑 → 差值 → 归一 → clamp → 输出」。`language_profile.md` 给 Methods 留了少量超长句额度,正是为它们服务。拆开会切断因果链,属于风格压过准确。

**规则打架时的判例**:难点枚举 `the reasons may be N folds: 1)…N)` 构式天生是长句(实测 48 词),与 40 词线直接冲突。**判枚举优先**,把各分项压到 4–15 词,让读者的实际停顿单位远小于总词数。重跑统计时这句会被标成超长句,属预期内误报,在工作笔记里登记,别反复回头拆它。

## 七、最容易漏掉的四件事

1. **原稿一个字节都不许变。** 全程只写 `revised/` 与 `polish/`,收工前对原稿做一次哈希或 diff 确认。
2. **`so that` 这类「看起来像特征其实不是」的构式。** 语料里它总共出现六次且四次集中在同一篇,**不是风格标识**。拆长句时它自然消失是净收益,不是损失,别误当特征保留。
3. **数字填入后要配套删除的声明。** 草稿里「还没跑」的声明与将来的比较结论互斥,通常散在三四处(摘要、各结果段末句、结论局限段)。**漏删一处,全文的诚实立场就自相矛盾。** 把这些位置列成清单写进意见书的「还没定的事」,提醒学生填数时一起处理。
4. **待填模板要预先定好说法档位。** 实验没跑完的稿子,给学生备的待填模板必须现在就定好:可核验的事实用 `The reason is that`,查不了的属性和不利结果用 `The reason may be that`;`slightly` 只许用于对手优势或自身劣势;强度词分好档。等填数时再定,就会出现摘要说 `significantly outperforms`、正文却在承认输了某指标的口径冲突。
