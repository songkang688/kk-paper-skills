## 一、推理链的标准形态

写任何方法类论文时，先把这条链填满，再动笔写章节。链条填不满就说明还有环节没想清楚，或者用户还没给足事实。

```
Problem
  → Representation Failure      （某类信息被丢弃 / 未被建模 / 丢失）
    → Design Principle          （从信息缺失抽象出的设计原则）
      → Module                  （以被丢失的信息命名）
        → Ablation Variant      （移除该模块后掉多少）
          → Main Result Claim   （在什么数据集上、比谁好、好多少）
```

**闭环核对数据**：22 篇中 18 篇 `Chain_Complete = yes`，4 篇 partial（17、21、30、31），全部因为没有消融小节，而不是因为诊断或模块缺失。模块层面 45 个模块中 38 个有对应消融变体（84%）。

## 二、三条核心模式

### RD1｜把表面症状收敛为"某类信息缺失"，再让模块名承载这类信息

不管起点是精度低、误报多还是速度慢，诊断的落点始终是"某类信息被丢弃/未被建模/丢失了"。紧接着提出的模块用这类信息命名，模块名本身成为诊断结论的重述。

**可核验数据**：45 个模块里 35 个（78%）的命名回指了被诊断为缺失的信息。

**操作**：
1. 写出表面症状（用户给的问题）
2. 追问一层：这个症状背后是哪类信息没被表示出来？
3. 用 `discard / does not involve / loses / is not modelled / ignores` 把它写成一句诊断
4. 给模块起名，名字里必须包含第 3 步那类信息的名称
5. 在 Introduction 与 Conclusion 里都保持这个对应关系

**年代下限 2016 年。** 2011 与 2012 的两篇独著用统计学习语言（泛化性能差、对旋转光照敏感），没有这一层。

### RD2｜互补双路：两分支承担不对称角色，融合本身要专门设计

先论证两类表示各有所长且缺陷互补，然后并列两条路，**最后把融合当成一个需要单独设计的模块**——这一步是关键，他很少用裸的 concat 或 add 了事。

**已观察到的不对称分工**（跨 12 年反复出现）：深/浅、粗/细、CNN/Transformer、空域/频域、空间/通道、分割/分类、两个坐标系。

**融合被单独设计的证据**：`Feature Complementary Module`、`Bi-directional Attention Gate`（双输入双输出）、`Multi-level Attention Coupled Module`、`Feature Fusion Module + Global Coefficient Path`、`Adaptive Feature Fusion`，以及 08 号那个"只含 add、convolution、activation 层的极小融合网络"。

**元论证句**：在提出结合类方法之前，先用一句话说明"不同路线各有长处，因此合并是自然的"。语料在 19、12、13 三篇里都有这句，措辞不同但功能一致。

改写示例（可直接用）：
- `Hybrid designs are able to retain the respective strengths of the two kinds of representations.`
- `Since the two families of features are complementary in nature, it is reasonable to combine them for stronger robustness.`

**注意**：12 与 13 的原句几乎同句且共用引用编号 [33]，独立证据实为 19 与 12/13 两组，因此本条 confidence 定为 medium。

**Avoid**：方法本身没有对偶性时不要硬造双路；不要用裸 concat 当融合——他明确把这当成被批评的对象（05 号的 `instead of feature concatenation or summation`）。

### RD3｜任务粒度阶梯：主动把问题定义得更难，并论证升级的合理性（限烟雾）

不只是换任务，而是**显式论证新任务比旧任务提供更多信息、也更难**，把粒度升级本身当成贡献。

可用句式：`<新任务> provides more information than <旧任务>, but it is far more challenging than <旧任务>.` / `<新任务> is a far more difficult task than <旧任务>.`

**配套动作**：粒度升级带来标注困难时，用合成数据解决而不是回退任务（3D 流体仿真生成 RGBA 纯烟并线性混合背景；图像合成生成分割数据集）。

**限烟雾系列。** 非烟雾五篇（去雾、医学分割 ×2、少样本、超分）不参与这个阶梯，直接用领域标准任务名。

## 三、三条次级模式

### RD4｜代价维度是一等目标（限轻量或高效类）
参数量、FLOPs、推理速度写进标题、摘要、结论，并在精度落后时用来完成非对称让步。用倍数表达优势（`approximately 57× fewer parameters`）；用"省得少、掉得多"反向论证模块必要性（`removing AFF reduces parameters by only 8%, but PSNR decreases by 0.16dB`）。

### RD6｜问题、模块、贡献、消融、图表五者互相镜像
Introduction 枚举的难点数、贡献列表条数、Methods 模块数、消融变体数、定性图面板组数之间保持对应关系，读者可以逐项对照。**这是一条可机械校验的自洽性要求。**

### RD7｜借用外部数学工具时先复述再改造
触发条件是**是否借用外部工具，不是年代**（05 号 2025 年借 Newton 插值，同样设了复述小节）。副作用：这类论文的目的从句密度会偏低，因为复述小节不需要交代"我们为什么造这个"。

## 四、批评落点的年代漂移

| 年代 | 主要攻击点 | 状态 |
|---|---|---|
| 2011–2021 | **阈值敏感性**：方法依赖预先指定的阈值，而阈值随场景与燃烧材料变化 | **限早期风格，写当代论文不得套用** |
| 2022 年后 | 感受野不足、长程依赖缺失、局部与全局信息的矛盾 | 当代可用 |

对应的设计倾向：用可学习的量替代人工阈值（用回归学置信比替代固定比值；用 AdaBoost 选特征替代预先指定特征；用学习的投影矩阵替代手工设计）。

## 五、单篇独特案例（留档，不作常规做法）

11 号（去雾）做了全语料唯一一次**元层面统一**：没有直接提新模块，而是先把三个已知先验统一到"通道最小值升序曲线"上，指出每个先验都对应曲线上的某个点，然后提出"取一个可调的点"作为新先验。贡献不是模块，而是一个把竞争者全部纳入的参数化框架。

**单篇证据，不得声称这是他的常规做法。**

## 六、明确不作为思维特征的项

1. `Inspired by ...` —— 学术论文通用叙述方式。保留的只有它在 Related Work 末段的**位置固定性**（19/19 篇），那属于结构规则。
2. "消融验证每个模块" —— 深度学习时代的领域标准做法。保留的是"消融变体按递进式逐级加回组件"这个具体形式。
3. "用合成数据解决标注困难" —— 烟雾领域已相当普遍。保留的是它与任务粒度升级的绑定关系。
4. 主题相关的技术偏好（LBP 家族、注意力机制、频域变换） —— 那是研究方向而不是思维方式。
