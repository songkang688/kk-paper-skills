### 1.5.0（2026-08-30）

**新增 `draft_workflow.md`：整篇初稿与中翻英的编排流程。** 此前从零起草只有单章节的串行流程（`workflow_and_templates.md`），出整篇初稿没有编制、没有融合步骤、没有 Word 输出；中文稿转英文稿则完全没有专门流程。

两种模式共用一套骨架：

- **模式一（从零起草）**：学生给证据包 → 问诊 → 父节点亲自建事实包（唯一事实来源）→ 五路分节子 agent 并行（Title+Abstract+Conclusion 一组、Introduction、Related Work、Methods、Experiments 各一路）→ 父节点六关融合 → tex/pdf/docx 三格式落稿。
- **模式二（中翻英）**：定位为**以中文稿为事实来源的重写**而非翻译。父节点先切节、先定死术语对照表，各路 agent 忠实于技术事实但按英文套路重排结构，每处挪位与删除都登记进确认清单。

设计要点：

1. **起草用并行、润色不用，理由写明**：润色是多人改同一份稿子必然撞车（1.4.0 已废除）；起草的各节是从零新写的不相交产物，只共享一份只读事实包，无共享可变状态，并行是净收益。省下的时间一部分要还给融合，融合六关（术语统一、模块-贡献-消融闭环、重复裁决、时态锚点全篇复查、页数按位置算、引用核对）是成败所在。
2. **Title+Abstract+Conclusion 必须一人写**：三者是同一组事实的三级压缩，模块宣告、强度词、诚实声明要三处同频。
3. **贡献列表在事实包里定草案**，Introduction 路只管措辞，避免两路各写一版融合时重写。
4. **交叉引用全用 `\ref{}` label**（label 名在事实包的图表规划里定死），编号由编译器结算。
5. **整篇论文级交付物加 Word 版**：pandoc 转 docx，定位是给导师批注的工作版，排版仍以 PDF 为准。查找顺序 `YFN_PANDOC` → PATH → 各系统常见位置；缺 pandoc 照常交 tex+PDF 并明确告知，附各平台安装命令，不静默跳过。
6. **产物文件夹统一约定（对所有工作流生效）**：一次任务的全部产物放进论文目录下的同一个任务文件夹（`polish-vN/`、`draft-vN/`、`c2e-vN/`，N 递增不覆盖），意见书、正稿、`_work/` 内部笔记都在里面，不散落到论文目录根。`polish_workflow.md` 的目录约定同步改为此制。

同步更新：`SKILL.md` 触发条件区分四条入口（单章节 / 整篇初稿 / 润色 / 中翻英）、问诊菜单扩到八项、四点五节加 Word 约定、文件索引加行、自检清单加整篇起草专用五项；`polish_workflow.md` 问诊菜单与目录约定改版；`workflow_and_templates.md` 开头标明与 `draft_workflow.md` 的分工（单章节归它，整篇编排归新文件）。

### 1.4.0（2026-08-30）

**润色流程从九子 agent 分工制改为老师亲自做，并新增接稿问诊。** `polish_workflow.md` 全文重写。

废除派发的理由：九个互不通信的 agent 必然撞车，父节点要花大量精力裁决冲突、统一口径、防互相覆盖；而稿子本身才三百来行，一个人从头读到尾对全文一致性的把握反而更好。多 agent 时代踩出来的经验全部保留——「先删后拆」「caption 迁移先行」「新资产降级为待办」「页面预算按位置算」这些原来的冲突裁决原则，现在转成了一个人干活时的先后顺序规则。

新增第零节「接稿先问诊」：学生交来稿子，先问三件事再动手——(1) 投哪儿（期刊/会议、页限、模板，决定末页规则与摘要词数区间；没定就按现有模板猜并明说让他确认）；(2) 要我做什么（七项菜单可多选：整篇润色 / 只改指定章节 / 只提意见不动稿 / 从零起草 / 提纲扩写 / 图表专项 / 格式核查）；(3) 改哪些部分（**不说默认全文**，但开工要交代一句「你没说范围，我按全文来了」）。问诊答案决定交付物形态；范围之外通读时看到的问题，只在意见书末尾提一句，不动手。

其余调整：

- 动笔顺序定为「正文顺流而下 → 图注 → Abstract/Title 最后 → 跨节归位核查」，因为摘要与标题是全文的浓缩，正文没定型前改它们是白改。
- 原 07 号 agent 的三分核查改为通读后的独立步骤「跨节归位核查」。
- 选了润色就不再单独交诊断报告，发现的问题直接进意见书并给改法，不让学生读两遍同一个问题；只要意见（菜单第 3 项）才单独出稿子意见。
- 工作账目统一记进 `_work/polish_notes.md`，意见书保持 `review_voice.md` 口径。
- `SKILL.md` 新增第一点五节「接稿先问诊」，触发条件、文件索引、自检清单同步更新（润色额外项从五项扩成六项，新增「开工前问过投稿目标与范围」）。

### 1.3.0（2026-08-30）

新增 `review_voice.md`：**审阅输出的口吻规范**，硬规范而非建议。此前的审阅输出写成了验收单，通篇是工具内部账目，作者拿着做不了任何事。

触发这次修订的是三句实际写出去的话：「35 项断言中 28 项通过、7 项未通过」（数字不指向任何一句要改的话）、「用 22 篇语料的 12-gram 索引（157,082 条）扫全文」（作者关心的是有没有抄，不关心怎么查的）、「规则：CORE-1 / X1 / M2 / C2，confidence high。现状：全文搜索 `To <purpose>, we <verb>` 及其变体，命中 0 次」（这串编号在作者脑子里对应不上任何东西）。第三句翻译成人话只有一行：**你全篇没有一处先说目的、后说做法的句子。**

规范定了五件事：

1. **口吻**：导师跟学生看稿子。用「你」，开头可以叫一声「同学」。讲问题从**读者读到这儿会怎么样**切入，不从规则切入。说完问题必须给到可直接粘贴的改法。该说不用改的地方要跟问题一样明确地讲。
2. **七类东西不许进输出**：规则编号与 confidence 等级、断言通过数、正则式与命中数、工具内部账目（n-gram 条数、脚本路径、「怎么重跑」）、自己的返工过程、语料篇数比例、大段规则对照表。唯一例外是作者主动问「你凭什么这么说」。
3. **规则到人话的对照表**：按全篇通用 / 摘要 / 引言 / 相关工作 / 方法 / 实验 / 结论 / 图表分组，每条规则给出跟作者怎么讲。写输出时只用右边那一列。
4. **把握程度改成口语**：confidence high 说「这个一定要改」，medium 说「不改也行，但改了更顺」；条件不满足的规则直接不提，不写「本规则不适用」。优先级也不用「必改/建议/可选」标签，在句子里说「这个必须改」「这个你看着办」。
5. **内部照跑，输出不露**：断言、句长统计、抄句检查、词数账全都照做——它们是判断依据，只是不写进输出。依据要留痕在工作记录里，作者追问时要能立刻拿出来。**把这条理解成「少做检查」是最严重的误读，规范里单列一节强调。**

同步改了三处配套：

- `SKILL.md` 新增第四点六节（审阅口吻的硬性约定，含被删掉的三句实例），第一节触发条件指向本规范，自检清单加一项。
- `polish_workflow.md` 的九个子 agent 提示词模板与输出结构全部换成新口吻：报告小节从「结论摘要 / 逐句建议（规则 ID + confidence + 优先级 + 词数）/ 净长度核算 / 主动放弃的规则」改为「先说不用改的地方 / 改后的完整版本 / 逐句说 / 长度账 / 我放弃了哪条要求 / 还没定的事」。同时明确了两条容易搞混的口径边界：**给 agent 的诊断可以带账目，给作者的不能**；**agent 返回给父节点的消息是内部通信要写全账目，它写出去的 md 不能带**。汇总报告拆成两截，正文给作者、末尾附核对清单。
- 提示词要点补了一条：口吻规范必须连着「但检查不减」一起写进去，否则 agent 会连统计一起省掉，交回一份读着亲切但没查过的意见。

### 1.2.0（2026-08-30）

新增 `polish_workflow.md`：**整篇润色已有英文草稿**的完整流程。此前 Skill 只有从零起草的流程（`workflow_and_templates.md`），改写现成稿只能逐节手动跑，没有分工、冲突裁决与验证闸门的规定。

这份流程是从一次真实任务里提炼的——一篇 ICASSP 5 页投稿（312 行 tex、115 个 `XX` 占位符、实验一次未跑），九个子 agent 分节润色，共 73 条逐句建议，父节点裁决八处冲突后真编译出修订稿。实测结果：超 40 词的句子 25 → 7（剩余 7 句全是登记在册的变换链保留项）、最长句 129 → 63 词、目的从句 0 → 11、`so that` 4 → 0，排版保持 5 页 / 0 overfull / 第 5 页仅参考文献。

文档包含五块内容：

1. **目录约定**：改后稿与改前稿共存，原稿全程只读，`revised/` 独立可编译，`polish/` 放九份报告加汇总。
2. **子 agent 提示词模板**：共同背景 / 硬红线 / 负责范围 / 评估点 / 输出结构 / 返回内容六段骨架。其中三处是实测有效的写法——强制要求「主动放弃的规则」一节（否则知情落差会被静默吞掉）、要求 agent 显式回答「我没有填任何数值」、以及要求它报告诊断报告的漏项（九个 agent 里六个报回了有效漏项）。
3. **八类冲突的裁决原则**：含「两个 agent 判断相反」时的三条判据，以及父节点覆盖节负责 agent 判断时的检验方法（拿 agent 自己的论据去逐对卡）。
4. **五组验证闸门**：排版一致性、占位符与技术常数正则计数、引用键集合比对、风格改善量化、剩余长句逐条归属。
5. **踩过的坑**：词数预算必须按位置算（总量 +13 词却把正文顶到了末页，因为增量集中在第 4 页末尾，而投稿格式规定末页只能放参考文献）；句长统计脚本跨公式块拼接会虚报出不存在的超长句；PowerShell 5.1 读无 BOM 的 UTF-8 会让中文哈希键名语法报错。

同时更新 `SKILL.md`：第一节触发条件指向本流程，第八节文件索引区分「从零起草」与「改写现成稿」两条入口，第九节自检清单加了整篇润色专用的五项。

### 1.1.0（2026-08-29）
新增输出约定：**每份交付物同时出 `.md` 与同名 `.pdf`**，规则见 `SKILL.md` 第四点五节，操作步骤见 `workflow_and_templates.md` 第 7 步，自检清单加了对应一项。

配套工具装在 skill 目录根：`md2pdf.py`（转换器，跨平台）、`md2pdf.ps1`（Windows 包装）、`md2pdf.sh`（macOS/Linux 包装）。两个包装脚本只负责定位 python 与按需装依赖，全部平台判断都在 `.py` 里，因此 `python md2pdf.py <目标>` 在任何系统上都等价可用。

**可移植性是明确的设计约束**（换电脑要能直接用）：
- 渲染器不写死。查找顺序为环境变量 `MD2PDF_ENGINE` → PATH（chrome / chromium / msedge / brave 等 9 个可执行名）→ Windows / macOS / Linux 三套常见安装位置。除 Chromium 系浏览器外也支持 `wkhtmltopdf` 与 `weasyprint`，用第一个找到的。
- 解析器不写死。首选 `markdown`，缺失时退到 `markdown-it-py`。
- python 不写死版本号。包装脚本按 PATH → `py` 启动器 → 安装根目录递归查找，并排除 Windows 的 App Execution Alias 占位程序（它能解析但无法运行）。
- 字体不写死。CSS 的字体栈按平台列全（雅黑 / 苹方 / Noto CJK / 文泉驿等），不依赖任何一台机器上的具体字体。
- 新增 `--check`：打印本机的 python、解析器、渲染器三项，缺哪项就给哪项的安装命令。换机器后先跑这条。

选浏览器渲染而不是 LaTeX，正是因为 LaTeX 路线每换一台机器都要重配 CJK 字体，而本 Skill 的产物经常在同一张表格里混排中文说明与英文论文正文。

实现中解决了四个具体问题，都是实测踩到的：
1. **表格窄列坍塌**：浏览器的自动布局会把两字的中文列压成每行一个字（`min-width` 与 `word-break: keep-all` 均无效，紧急换行规则会覆盖 keep-all）。改为按内容长度算出每列宽度写进 `<colgroup>` 并配 `table-layout: fixed`。
2. **BOM 吃掉首行标题**：PowerShell 的 `Out-File -Encoding UTF8` 会写 BOM，`\ufeff#` 不被识别为 ATX 标题。改用 `utf-8-sig` 读取。
3. **硬换行段落变成 ragged**：初版启用了 `nl2br` 扩展，会把段落内的软换行固化成 `<br>`。已移除。
4. **相对路径静默失败**：传相对路径时浏览器把 `--print-to-pdf` 的目标解析到它自己的工作目录，不报错也不出文件。转换前统一 `resolve()` 成绝对路径。

规则数量、证据裁决与 confidence 未变动——本次是交付方式的变更，不涉及风格规则。

## 五、已知局限

### 5.1 证据层面

1. **Discussion 的实际样本量是 1。** 22 篇里真正独立成节且与 Conclusion 分开的只有 21 号一篇（148 词）。相关规则 confidence 上限为 low，`section_playbook.md` §7 的骨架是**推断**而非观察。11 号那段读起来很像标准 Discussion 的文字是语料清洗时合成的，严禁引用为证据。
2. **年代与方法范式不可分离。** 按年份切（8/14）与按范式切（7/15）只差 1 篇论文，两组指标几乎逐项一致。所有标为"年代效应"的项都可能实际是范式效应。
3. **venue 与年代部分共线。** IEEE 烟雾论文 5/6 在晚期，Elsevier 烟雾论文 4/9 在早期。Conclusion 的目的从句密度差 3.4 倍（IEEE 11.2/k vs Elsevier 3.3/k）无法归因。
4. **控制年代后的 Tier 比较在 A1 侧只有 2 篇**（07、36），只能作方向性参考。
5. **KSII 只有 2 篇**，该 venue 的所有差异不作判定。
6. **表格内容在全语料 PDF 提取时普遍丢失**，只有图表标题存活。无法覆盖表格内部排版、字体、配色。按规则不猜绘图软件与字体名。
7. **公式重建标记遍布 11 篇**，本 Skill 不对公式内容做风格判断。
8. **02 号不可用于引用密度结论**（清洗版本的括号引用数为 0，提取时把编号引用替换成了作者名叙述）。
9. **17 号提取质量中低**（公式全部排除、Introduction 两处截断），不可用于任何长度或密度统计。
10. **课题组模板与个人特征的边界只做了部分分离。** P4 用"传给学生会衰减"作为个人特征的判据（Tier B 的 Conclusion 目的从句密度为 0、非对称让步退化为 `comparable`、A3 的 hedge 密度最低），但结构骨架本身仍可能是实验室模板。

### 5.2 测试层面

11. **无第三方盲测。** 逆向识别只有一正一负两个样本，且执行者与 Skill 作者是同一个。无法证明该风格能在真实盲测中与其他研究者区分开。
12. **未测完整论文级一致性**（跨章节术语、引用编号、图表编号连贯性）。
13. **未测 Discussion 独立成节的生成质量**（样本量 1，无法判定对错）。
14. **未测早期风格（2011–2017）的生成。**
15. **未测语言质感。** 语料保留了大量作者原始笔误（`Datesets`、`long-rang`、`cocatenated` 等），本 Skill 明确不复刻笔误，但未验证生成文本是否因过度规范化而失去原有质感。
16. **未做多次独立生成的稳定性测试。** 只生成了一次。

### 5.3 使用层面

17. **不得给任何风格指标设数值目标。** 目的从句密度在 Conclusion 从 3.3/k 到 11.2/k 都出现过。只能给结构约束。
18. **不得把 Tier B 与 A3 的写法当作者本人风格。** 那些差异是"作者本人 vs 学生执笔"的分界线。
19. **不得刻意写被动语态。** 那是 2011–2019 的年代特征，2020 年后 Conclusion 的被动密度中位数是 0。
20. **这套规则描述的是语料的中心趋势，不是唯一合法形态。** 20 号（Tier A1，提取质量最好之一）同时违反多条主流规则，其简约形态在"借用成熟工具 + 小改动"类工作上可能更合适。

## 六、不适用场景

| 场景 | 原因 |
|---|---|
| 非计算机视觉 / 图像处理类论文 | 语料只覆盖五类视觉任务 |
| 中文论文 | 只建模英文写作 |
| 综述类论文 | 语料 22 篇全部是方法型期刊论文，无 survey |
| 会议论文的压缩格式 | 语料全部按期刊形态写作 |
| 理论证明为主的论文 | 语料的论证以工程设计与实验为主，无定理-证明结构 |
| 要求深度独立 Discussion 章节 | 样本量 1，只能给推断骨架 |
| 用户无法提供真实实验数据 | 事实性红线禁止编造数值 |

## 七、维护建议

1. **补语料优先补三处**：独立 Discussion 章节的样本（当前 1 篇）、2018–2022 年间的 Tier A1 论文（当前该区间 A1 只有 07 一篇）、非烟雾主题的 Tier A1 论文（当前只有 36 一篇）。
2. **补测试优先补两项**：引入第三方作者样本做盲测；做多次独立生成的稳定性测试。
3. **重新裁决的触发条件**：若新增语料使某条 low 规则的支撑篇数达到 2 篇以上，应重新走 P5 的裁决流程，并同步更新 `evidence_register.csv` 与白/黑名单。
4. **修改风格规则时必须同步四处**：`evidence_register.csv`（证据与定级）、`core_pattern_whitelist.md` 或 `overgeneralization_blacklist.md`（归属）、`section_playbook.md`（可执行指令）、`SKILL.md`（若涉及主干或红线）。
5. **每次修改后重跑两项检查**：12-gram 原句复制检查（`_p5_ngram.ps1`）与生成测试的 37 项断言（`_p6_check.ps1`）。
