# 审稿意见回复工作流：从审稿意见到逐条回复信与修改稿

适用场景：学生投稿后收到审稿意见（期刊 major/minor revision，或会议 rebuttal），要求产出逐条回复与配套修改稿。

**角色设定：你是导师，亲自带学生打这一仗，不派子 agent。** 回复信是一个整体的说服文本，各条回复之间要互相呼应（审稿人 A 和 B 提了同一个问题要口径一致），一个人从头写到尾才守得住全局。

不适用：还没投稿的稿子（走 `polish_workflow.md`）；从零写稿（走 `draft_workflow.md`）。

---

## 零、接稿先问诊

拿到意见先问四件事，一次问完：

1. **结果是什么？** major / minor / reject-and-resubmit / 会议 rebuttal。这决定整个策略：minor 求稳少动；major 要证明"认真对待了每一条"；rebuttal 只有回复没有改稿机会，且常有严格字数限制（如一页），要做优先级取舍。
2. **投的哪儿、格式要求是什么？** 有的期刊要求单独的 response letter + 标色修改稿（highlighted version），有的要求逐条嵌入；会议 rebuttal 有模板和字数上限。学生不清楚就让他把编辑邮件原文发来。
3. **哪些意见你已有弹药，哪些要补实验？** 逐条过一遍：已有数据能回的 / 改写就能回的 / 必须补实验的 / 打算不同意的。**补实验的事只能学生自己跑**，红线不变：没跑出来的数字一个不许出现在回复里。
4. **截止日期。** 决定要不要建议学生申请延期，以及补实验清单怎么排优先级。

## 一、产物约定：一次任务一个文件夹

```
<论文目录>/rebuttal-v1/
  00-意见总览与策略.md / .pdf   ← 给学生的作战图（见第二节）
  response-letter.md / .pdf     ← 逐条回复信（正式版，英文），需要 docx 就用 pandoc 转
  revised/                      ← 修改稿，与提交版可直接 diff
    main.tex / main.pdf
    main-highlighted.pdf        ← 期刊要求标色版时才有（\textcolor 或 latexdiff）
  _work/
    point_ledger.md             ← 意见-回应-改动三联账（内部）
```

原稿（上一版提交稿）全程只读，沿用 `SKILL.md` 的共存与 md+PDF 约定。

---

## 二、第一步：把意见拆成台账，先定策略再动笔

通读全部意见，在 `_work/point_ledger.md` 里逐条登记：编号（R1-1、R2-3 这样）、原文、类型、策略、涉及稿子哪些位置。**同一问题被多人提到的要标出来**——这是最要紧的信号，说明问题是真的，而且各条回复必须口径一致。

每条意见归入四类之一，策略随类走：

| 类型 | 策略 |
|---|---|
| **同意，能改** | 改稿 + 回复里指出改在哪。最多数，也最简单 |
| **同意，但要补实验** | 列进补实验清单给学生排期；数据回来前这条的回复只能写计划，不写结果 |
| **不同意** | 必须有证据（文献、既有数据、逻辑）才许不同意；没有证据就不叫不同意，叫不服气。全信里不同意的条数要克制，都不同意等于告诉编辑"我没打算改" |
| **审稿人误解了** | **一律先改稿再解释。** 误解 = 原文没写清楚，这是写作问题不是阅读问题。回复写"我们已把该处改写为……"，绝不写"正如原文已经说明的" |

`00-意见总览与策略.md` 用导师口吻（照 `review_voice.md`）把台账讲给学生听：哪几条是送分题、哪几条最要命、哪几条要补实验、我建议不同意的是哪条以及凭什么。**补实验清单单独列一节**，按"不补会不会被拒"排序，别按实验难度排。

## 三、第二步：写逐条回复

### 回复信骨架

开头一段感谢 + 总述改动（新增了什么实验、重写了哪节），然后逐审稿人、逐条：

```
Comment R1-1: （审稿人原文，完整照抄，不许删节或改写——删节会被当成回避）

Response: （三步走）
  1. 表态：We thank the reviewer / We agree / We respectfully disagree
  2. 回应正文：改了什么、为什么这么改；或者不同意的证据
  3. 落点：Changes: Section III-B, page 4, lines 12–18 + 引用修改后的原文（引文用
     引号或斜体，让审稿人不用翻稿子就能看到改动）
```

### 语气纪律（这是最容易翻车的地方）

- **不卑不亢。** 每条都可以感谢，但不要每条都 `We sincerely thank the reviewer for this insightful comment`——通篇高频吹捧读起来是敷衍。感谢在开头统一给足，逐条里该干什么干什么。
- **禁用清单**：`As we clearly stated`（=你没看仔细）、`The reviewer seems to have missed`（同上）、`Obviously`、`It is well known that`（=你连这都不知道）。这些句式每一个都在挑衅。
- **不同意的写法**：先复述审稿人的合理性（`We agree that X would be a concern if ...`），再给证据，最后留台阶（`We have added a clarification in Section IV to make this explicit`）——即使不同意，稿子里也要留下这条意见的痕迹，让审稿人看到自己的意见被认真对待了。
- **输掉的指标、补不出的实验，如实说。** 事实性红线全部沿用：不编数字、不编引用、不夸大补充实验的结论强度。`slightly` 的非对称让步用法在这里同样适用。

### 修改稿的写作

新增或重写的正文段落**回到 `section_playbook.md` 的对应章节规则写**——回复信是应用文，修改稿仍然是论文。改动尽量集中、可定位，别顺手把审稿人没提的地方大面积重写（那会引来新一轮意见）；确实顺手发现的问题，小的直接改并在回复信末尾统一列一句 `Additional minor corrections`，大的记进意见总览让学生决定。

## 四、第三步：验证闸门（回复信版）

```
# 1. 覆盖率：台账里每条意见都有对应回复；回复编号与意见编号一一对应，无漏条
# 2. 承诺兑现：回复里每个 "Changes: ..." 都能在 revised/ 里定位到真实改动；
#    反向也查——修改稿里的实质改动都在某条回复或 Additional corrections 里有交代
# 3. 口径一致：同一问题的多条回复（不同审稿人）表述一致；回复里引用的修改后原文
#    与修改稿逐字一致
# 4. 语气扫描：禁用清单逐个正则查一遍
# 5. 沿用润色闸门：页数与末页规则、占位符与技术常数计数、引用键集合、编译干净
# 6. 格式合规：response letter 的格式（单独文件/嵌入式/字数上限）符合问诊时确认的要求
```

台账（意见-回应-改动三联）留在 `_work/`，交付物里不出现内部账目。

---

## 五、最容易踩的三个坑

1. **回复信说改了、稿子里没改。** 这是致命错误，审稿人核对发现一处，整封信的信用清零。所以闸门第 2 条必须双向查。
2. **rebuttal（会议）当成 revision（期刊）打。** 会议 rebuttal 没有改稿机会，字数极紧，策略完全不同：只回最伤的两三条，用已有数据回，其余合并简答。把期刊那套逐条长文搬过去会淹掉重点。
3. **补实验的结论先写进回复。** 学生说"这实验肯定能跑赢"，也不许先写结论占位。回复信定稿必须在数据回来之后；赶截止日期就把这条的回复留到最后一刻填,或如实写 `we are conducting ...` 的计划式表述（仅在该期刊允许阶段性回复时）。
