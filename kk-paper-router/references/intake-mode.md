# 接稿吃透模式（任何干活之前的第一步）

用户第一次给论文全文、稿件文件或代码包时，先走本流程完全吃透，再进入任何
其他模式。没有吃透档案就直接润色、审稿、改代码，属于违规操作。

## paper_context 是稿件级公共资产（先读这条）

吃透档案 `paper_context/<稿件名>/` 建在论文所在目录（论文旁边），与各次投稿的
工作目录（如 `kkstoryline_work_<venue>_<时间戳>/`）同级。它只跟这篇稿子绑定，
不跟投稿目标和时间戳绑定，所以目录名不带 venue、不带时间戳。一篇论文只建一份，
换期刊重投、换 skill 干活都复用同一份，不重复提取。

- **稿件名**：用论文文件名主干去掉扩展名和版本号（`MyPaper_v3.pdf` → `MyPaper`），
  或用户指定的题目短名。一旦在 anchor 里定下，后续所有 skill 一律沿用，
  不得各自另起名字，否则公共资产就散了。
- **谁先需要谁补建**：任何 skill 需要某项基础提取而 paper_context 里没有时，
  就地补建到 paper_context（不是建在自己的工作目录里），后来者接着复用。
  只有某 skill 需要额外的特定切分或标注时，才在自己工作目录里补那一份特殊的。

## 第 1 步：锚定基准

- 确定唯一基准文件，记录绝对路径。多个版本时以用户给的最新版为准，
  旧版本一律不看。
- PDF 先转成可检索文本（pdf-to-md 或 pdf-to-tex），LaTeX 工程找到主 tex，
  代码包解压后找到入口。
- 在 `paper_context/<稿件名>/00-anchor.md` 写下：基准文件绝对路径、版本标识、
  接稿时间、用户交代的背景与目标 venue（官方短名，如 TIP、ICASSP）。没给
  venue 先问再建档。档案目录本身不加时间戳（跨轮次复用），venue 写在
  anchor 里。

## 第 2 步：全文精读吃透

论文类，逐项提炼落盘到 `paper_context/<稿件名>/01-digest.md`：

- 结构树：章节层级，每段一句话要点。
- 贡献声明：作者声称的每条贡献，原文位置。
- 方法核心：模型结构、关键公式与符号表、创新模块的机制描述。
- 实验设置：数据集、指标、baseline、超参、消融设计。
- 数值表：摘要、正文、表格里出现的所有关键数字，标注位置。
- 图表清单：每个图表的编号、标题、想说明什么。
- 术语表：术语与缩写的首现位置和用法。
- 引用概况：关键引用支撑了哪些论断。

代码包类，落盘到 `paper_context/<稿件名>/02-code-map.md`：

- 目录结构与模块职责。
- 核心类和函数：定义位置、输入输出、相互调用关系。
- 训练入口、配置文件、依赖清单。
- 用户明确指定为基准的组件（如 LoRA 定义）单独摘出，标注禁止改动。

## 第 2 步补充：基础提取产物（格式转换与切分，公共复用）

除了上面的分析类档案，把对论文的机械提取产物也放进 `paper_context/<稿件名>/`，
供 kkstoryline、审稿、终检等直接复用，任何 skill 不重复转换：

- `paper.md`(+`images/`)：PDF/docx/tex 转成的可检索全文与抽出的图。
- `sections/`：按章节切分的分节文件（s1 标题+摘要+结论、s2 引言、s3 相关工作、
  s4 方法、s5 实验、s6 图表与杂项），kkstoryline 六路润色直接用。
- `paragraph_index.md`：每节段落编号、每段首句摘录、段落总数，kkstoryline
  第 5 步机械验收的依据。

这些是按需生成的公共资产：第一个需要它们的 skill（通常是 kkstoryline 第 1 步）
生成后留在这里，其他 skill 只读不重复造。

## 第 3 步：吃透汇报

- 用三五句话向用户汇报：这篇论文做了什么、核心贡献、方法主线、实验结论，
  以及发现的疑点（如有）。让用户确认理解无误。
- 汇报不展开全文复述，档案在盘上，用户要细节随时能查。

## 第 4 步：后续纪律（所有模式都要遵守）

- 此后每个模式（润色、审稿、终检、对比、rebuttal、找创新点、写代码）启动时，
  必须先读 `00-anchor.md` 和 digest，带着基准路径干活，一切判断以这篇
  论文为核心，不许脱离稿件空谈。
- 需要论文全文文本、分节或段落索引时，先查 paper_context 有没有 `paper.md` /
  `sections/` / `paragraph_index.md`，有就直接复用，没有才补建到 paper_context，
  绝不各自把 PDF 重新转一遍。
- 子 agent 派发时，prompt 里必须带上基准文件路径和 `paper_context` 档案路径。
- 用户给了新版本就更新 anchor 和 digest，并在 anchor 里记一行版本变更，
  旧版作废。
- 档案与实际稿件冲突时，以稿件现文为准并回头修档案。
