# 接稿吃透模式（任何干活之前的第一步）

用户第一次给论文全文、稿件文件或代码包时，先走本流程完全吃透，再进入任何
其他模式。没有吃透档案就直接润色、审稿、改代码，属于违规操作。

## 第 1 步：锚定基准

- 确定唯一基准文件，记录绝对路径。多个版本时以用户给的最新版为准，
  旧版本一律不看。
- PDF 先转成可检索文本（pdf-to-md 或 pdf-to-tex），LaTeX 工程找到主 tex，
  代码包解压后找到入口。
- 在 `paper_context/<稿件名>/00-anchor.md` 写下：基准文件绝对路径、版本标识、
  接稿时间、用户交代的背景与目标 venue。

## 第 2 步：全文精读吃透

论文类，逐项提炼落盘到 `paper_context/<稿件名>/01-digest.md`：

- 结构树：章节层级，每段一句话要点。
- 贡献声明：作者声称的每条贡献，原文位置。
- 方法核心：模型结构、关键公式与符号表、创新模块的机制描述。
- 实验设置：数据集、指标、baseline、超参、消融设计。
- 数值表：摘要、正文、表格里出现的所有关键数字，标注位置。
- 图表清单：每个图表的编号、标题、想说明什么。
- 术语表：术语与缩写的首现位置和用法。
- 引用概况：关键引用支撑了哪些论断。

代码包类，落盘到 `paper_context/<稿件名>/02-code-map.md`：

- 目录结构与模块职责。
- 核心类和函数：定义位置、输入输出、相互调用关系。
- 训练入口、配置文件、依赖清单。
- 用户明确指定为基准的组件（如 LoRA 定义）单独摘出，标注禁止改动。

## 第 3 步：吃透汇报

- 用三五句话向用户汇报：这篇论文做了什么、核心贡献、方法主线、实验结论，
  以及发现的疑点（如有）。让用户确认理解无误。
- 汇报不展开全文复述，档案在盘上，用户要细节随时能查。

## 第 4 步：后续纪律（所有模式都要遵守）

- 此后每个模式（润色、审稿、终检、对比、rebuttal、找创新点、写代码）启动时，
  必须先读 `00-anchor.md` 和 digest，带着基准路径干活，一切判断以这篇
  论文为核心，不许脱离稿件空谈。
- 子 agent 派发时，prompt 里必须带上基准文件路径和 `paper_context` 档案路径。
- 用户给了新版本就更新 anchor 和 digest，并在 anchor 里记一行版本变更，
  旧版作废。
- 档案与实际稿件冲突时，以稿件现文为准并回头修档案。
