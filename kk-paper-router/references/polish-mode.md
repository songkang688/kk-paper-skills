# 润色模式（输出契约，必须逐条遵守）

执行者：`scipilot-writing-skill`。流程：

1. 判定载体（`.tex` / Word / 纯文本）和语言方向：按用户给的文件后缀与文本本身
   自行判定，不停下来问。**范围默认全文——用户直接给了论文文件或整篇正文，
   就是全文润色，不问范围**；只有他贴了某一段、或点名某一章时，才收窄到那个范围。
2. 拆分是三级，一级都不许跳：

   a) **先把全文切成几个部分**：按章节切（Abstract、Introduction、Related Work、
      Method 各小节、Experiments、Conclusion），单章过长的再切细。切完先把部分
      清单列出来，每部分标明覆盖的章节与起止位置。
   b) 每个部分内部按段落拆。
   c) 每段再拆成句子。

   **整篇润色（部分数 ≥ 5）按部分并行派子 agent**，一个子 agent 只管自己那一两
   个部分，互不引用对方产文。派发时必须把本文件的绝对路径或 11 条原文写进 prompt，
   不许让子 agent 自己找（做法同 kkstoryline 第五节 e) 条）。子 agent 一律只产
   五段句卡 md、不转 PDF；父进程按部分原顺序拼成一份总对照 md 再转 PDF。
   切分清单的部分数、各部分句数、拼接后总句数三者必须对得上，缺句就返工。
   **拼完必做合并复审连贯性**：各部分是分头改的，合起来专查衔接不顺、术语/符号
   前后不一、同处两版打架、指代断链、重复表述，把统一处理写进总对照末尾的
   「汇总复审」一节，涉及英文正文的回填对应句卡的「改后」并同步 final，保持一致。
3. **每一句独立执行一遍润色**，遵守 scipilot 铁律（保守修改、只动表达不动数值、
   载体格式分流）。原句已够好就判「无需修改」，不为改而改。
4. 全部句子跑完后，按原文顺序一句出一张**五段句卡**（`::: card` 围栏，
   md2pdf 转 PDF 时渲染成带米色标题条、五个彩色标签的圆角卡片，比横向表格清楚）：

   ```
   ::: card <章节> · 句N
   **改前** 完整原句
   **改后** 完整可直接替换的句子
   **改前翻译** 原句中文意思（让只看中文的人也懂原句在说什么）
   **改后翻译** 改后中文意思（对照看清改了哪里）
   **为什么改** 动了哪几处 + 为什么、触发 KK 11 条哪几条，中文
   :::
   ```

   - `**改前**` 必须是完整原句，`**改后**` 必须是完整可直接替换的句子。
   - **语言分工**：`**改前**` `**改后**` 是要落进英文稿的，必须纯英文，一字不夹中文、
     不中英混排、中文标点不进英文句；`**改前翻译**` `**改后翻译**` `**为什么改**`
     是讲给作者听的，用中文。
   - 禁止缩写、禁止「同上」「略」「...」占位。长没关系，精细到逐句才是句卡的意义。
   - 无需修改的句子也要出卡片，`**改后**` 与 `**改前**` 一致，`**改后翻译**` 写
     「（未改）」，`**为什么改**` 写清它为何已经成立、不需要动。
5. 输出位置：
   - 输入不超过两段（或一句）：句卡直接放对话框。
   - 输入超过两段：写成 md 文件，路径
     `polish_reports/<venue>_<YYYYMMDD-HHMM>-润色对照.md`
     （放当前工作区），对话里给路径、句子总数、修改句数和主要问题类型摘要。
     落盘后立即转同名 PDF，多份分片先合并成总版再转。venue 用官方短名，先从
     `paper_context` 的 anchor 复用，查不到才在开跑前一次问清，之后一路润到交付。
     例：`polish_reports/TIP_20260831-1430-润色对照.md`
   - **md 顶部写封面 frontmatter**（md2pdf 会渲染成酒红封面页 + 右上运行页眉）：
     `title`、`header`（如「{venue} · 全文润色」）、`stamp`、`subtitle`、若干
     `meta_键: 值`（文件编号/文档角色/处理模式/技能路由/主要依据/事实边界）。
6. **出完整改后终稿（final）**：句卡是中间产物，光有它不算交付完。把每句「改后」
   按原文顺序拼回整篇，出一份可直接用的完整改后稿——载体是 `.tex` 就落
   `polish_reports/<venue>_<YYYYMMDD-HHMM>-改后终稿.tex`，是 Word/纯文本就落同名
   `.docx`/`.md`，验收后连同句卡一起转 PDF。这份 final 的每一句必须和句卡的
   「改后」逐句一致，且**通篇纯英文**（这是要投出去的稿子，不许夹任何中文注释或说明）。整篇范围必出 final；只润一段或一句时，句卡里的改后即成稿，
   不必另拼。这与 kkstoryline 的 `final_paper`、yfnskills 的 `revised/` 是同一层交付。
7. 交付前跑 scipilot 的 `scripts/writing_lint.py` 自检，命中 FAIL 必须修复或如实报告。

## KK 语句风格追加要求（11 条，与上面输出契约同时遵守）

适用范围是论文正文语句。与 scipilot 铁律冲突时，技术准确与证据边界优先。

1. 学术论文风格。
2. 尽量不要长难句。一句话只说一件事，三个从句以上的句子拆成两句。
3. 论文正文尽量不用冒号。报告和表格里不受此限。
4. 不要有语法错误。
5. 写得简单通俗易懂，适当润色。
6. 不要用不常用、晦涩难懂的词，用更直白直接的表述。生僻高级词一律换成
   该领域最常见的说法。
7. 拿不准风格时，参考目标期刊已发表论文同一章节的写法、风格和用词，
   模仿写作套路，但只学句式结构，不照抄句子。可用 scipilot 的
   `references/journal_styles.md` 和 research-paper-writing 的 section guides。
8. 用户会提供写作思路和依据，以用户本次给的数据资料为准，其他一律只作参考。
   拿不准时出 2 到 3 个版本让用户选，需要对比推荐时转 `paragraph-compare-polish`
   出对比表。
9. 润色执行者是 `scipilot-writing-skill`，章节叙事问题调 `research-paper-writing`。
   涉及用户特定项目的稿件时叠加对应项目 skill（如烟雾分割 PR 稿叠加
   `zerosmoke`），项目事实以项目 skill 记录为准。
10. 不要堆叠太多 a b c d 式并列，太人机。用因果、递进、转折把点串成连贯段落，
    确需列举时不超过三项。
11. 允许适当学术包装，突出贡献感，但断言强度不得超过证据强度，不得引入
    不存在的贡献、结论或因果。

自查闭环：每次改完，除用户指出的问题外，还要按这 11 条整体复查该段落，
发现违反项一并改进，并在修改日志里注明。

版本纪律：始终以用户给的最新版文件为唯一基准重新读，旧版本一律不看。

档案互通：稿件已有 `paper_context/<稿件名>/` 吃透档案时，润色前先读档案，
术语用法、事实与数值以档案加基准稿为准，改写不得与档案记录的贡献和
结论冲突。整段以上的润色若发现事实性疑点，先报问题再动笔。
