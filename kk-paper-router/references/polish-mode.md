# 润色模式（输出契约，必须逐条遵守）

执行者：`scipilot-writing-skill`。流程：

1. 判定载体（`.tex` / Word / 纯文本）和语言方向，用户没说先问一句。
2. 拆分：先按段落拆，再把每段拆成句子。
3. **每一句独立执行一遍润色**，遵守 scipilot 铁律（保守修改、只动表达不动数值、
   载体格式分流）。原句已够好就判「无需修改」，不为改而改。
4. 全部句子跑完后汇总成四列对照表：

   | 改前 | 改后 | 改了什么 | 为什么 |

   - 改前必须是完整原句，改后必须是完整可直接替换的句子。
   - 禁止缩写、禁止「同上」「略」「...」占位。
   - 无需修改的句子也要进表，改后写「无需修改」，为什么写清它为何成立。
5. 输出位置：
   - 输入不超过两段（或一句）：对照表直接放对话框。
   - 输入超过两段：写成 md 文件，路径 `polish_reports/<YYYYMMDD-HHMM>-润色对照.md`
     （放当前工作区），对话里给路径、句子总数、修改句数和主要问题类型摘要。
6. 交付前跑 scipilot 的 `scripts/writing_lint.py` 自检，命中 FAIL 必须修复或如实报告。

## KK 语句风格追加要求（11 条，与上面输出契约同时遵守）

适用范围是论文正文语句。与 scipilot 铁律冲突时，技术准确与证据边界优先。

1. 学术论文风格。
2. 尽量不要长难句。一句话只说一件事，三个从句以上的句子拆成两句。
3. 论文正文尽量不用冒号。报告和表格里不受此限。
4. 不要有语法错误。
5. 写得简单通俗易懂，适当润色。
6. 不要用不常用、晦涩难懂的词，用更直白直接的表述。生僻高级词一律换成
   该领域最常见的说法。
7. 拿不准风格时，参考目标期刊已发表论文同一章节的写法、风格和用词，
   模仿写作套路，但只学句式结构，不照抄句子。可用 scipilot 的
   `references/journal_styles.md` 和 research-paper-writing 的 section guides。
8. 用户会提供写作思路和依据，以用户本次给的数据资料为准，其他一律只作参考。
   拿不准时出 2 到 3 个版本让用户选，需要对比推荐时转 `paragraph-compare-polish`
   出对比表。
9. 润色执行者是 `scipilot-writing-skill`，章节叙事问题调 `research-paper-writing`。
   涉及用户特定项目的稿件时叠加对应项目 skill（如烟雾分割 PR 稿叠加
   `zerosmoke`），项目事实以项目 skill 记录为准。
10. 不要堆叠太多 a b c d 式并列，太人机。用因果、递进、转折把点串成连贯段落，
    确需列举时不超过三项。
11. 允许适当学术包装，突出贡献感，但断言强度不得超过证据强度，不得引入
    不存在的贡献、结论或因果。

自查闭环：每次改完，除用户指出的问题外，还要按这 11 条整体复查该段落，
发现违反项一并改进，并在修改日志里注明。

版本纪律：始终以用户给的最新版文件为唯一基准重新读，旧版本一律不看。
