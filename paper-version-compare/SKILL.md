# 同一篇论文多版本多维度对比评价

按 [references/protocol.md](references/protocol.md) **逐字执行**，共 44 节：
任务定位识别、顶刊质量评估、贡献真实性检查、创新链条完整性、审稿人攻击点、
评分体系、强制对比表、逐版本评审、Pairwise 对比、排名、合并策略、主线设计、
医学/遥感/实例/全景附加审查、PDF 输出要求、最终强制结论，全部照做。

执行要点：

1. 不迎合用户偏好，所有版本都不够顶刊时直说。
2. 不以复杂度代替创新性，按协议第 3.2 节识别伪创新与模块堆叠。
3. 所有评价必须有文本证据，缺信息标「信息不足 / 无法判断」，不虚构。
4. 综合评分含短板效应，性能最高的版本不自动获胜（协议第 34 节）。
5. 结论必须明确排名，禁止「各有优势」收尾，最终强制结论八项不得遗漏
   （协议第 44 节）。
6. 用户要 PDF 时按协议第 40 节结构生成正式评审报告。

与其他 skill 的边界：同一段落的多个英文表达版本对比走
`paragraph-compare-polish`；单版本论文的审稿走审稿模式（5 子 agent）。
本 skill 处理的是整篇方案或稿件级的多版本比较与主线抉择。

与其他 skill 互通：各版本已有 `paper_context/` 吃透档案时先读档案再评。
排名和合并策略定下后，用户要落地改稿的，转 kk-paper-router 润色模式
（四列对照表加 11 条风格规则）执行；主线需要补新章节的走写初稿模式。
